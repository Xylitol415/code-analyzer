# 记忆与知识复用验证记录

环境：2026-10-19，macOS arm64，Apple M4，Node.js 26.8.2，`@zvec/zvec@0.7.1`。

## 原生检索

实际安装的 npm 原生包支持无向量字段的 FTS collection、jieba 中文分词及 BM25 查询；不需要 Embedding。适配器按项目加跨进程锁，每次打开、操作、关闭 collection，SQLite 保存权威状态和可重放 outbox。

1 万条重建测试先暴露单次写入最多 1024 条的限制，加入失败回归后改为分批写入。独立 Node 进程竞争时，原有 0.2 秒锁重试不足以等待冷启动，改为约 6 秒预算。超出预算的索引操作保留 outbox，后续知识操作／检索重试；不保证无限等待。

`npm run memory:benchmark`：每个规模 5 个独立冷进程，各查 21 次；首查为冷查询，余下共 100 次统计热查询。每次查询都包括锁、打开和关闭。语料是重复的合成中文静态代码说明，不能代表真实业务语料或并发服务容量。

| 规模 | 冷查询 P50 / P95 | 热查询 P50 / P95 | 重建时间 |
| --- | --- | --- | --- |
| 1,000 | 219 / 322 ms | 117 / 200 ms | 1.20 s |
| 10,000 | 259 / 342 ms | 139 / 239 ms | 2.47 s |

原始结果：[原生性能 JSON](2026-10-19-memory-benchmark.json)。其中 `coldProcessMs` 包含 Node 启动及全部 21 次查询，不是单次请求时延。独立进程并发写入均保留；测量时父进程 5 ms 定时器仍运行，最大延后分别 15.5 / 32.2 ms。生产 worker 另有实际 Git 快照、原生重建时主事件循环继续运行的回归测试。

检索采用 300 ms 软预算，冷启动或锁等待时可以跳过本轮证据。它不是整个请求的硬时限：权威版本校验及同 worker 中已排队操作仍可能增加等待。直接复用走 SQLite，不依赖 FTS 可用性。索引丢失可重新播种；损坏索引本轮降级，后续重建；这些均有真实 worker 回归。

## 复用边界样例

`npm run memory:evaluate`：20 个合成代码问题族，开发与验收各 10 个，每族 8 个场景，共 **160 / 160**。分别验证同问题命中、相似措辞携带适用条件、不适用问题不直接返回、跨项目、策略变化、脏工作区、提交变化、撤回。

原始结果：[边界评估 JSON](2026-10-19-memory-evaluation.json)；数据：[固定问题族](../../tests/fixtures/memory-families.json)。相似问题保留相同符号名称以检验词法检索，不宣称独立真实语料的语义召回能力。验收集未用来调整分词参数或排序权重。

运行时／HTTP 集成测试验证了审核后新会话直接返回、模型方法若被调用即失败、requestId 重试不增加消息、真实历史恢复仍有回答 ID；生成期间源码变化、知识撤回、最终核验不可用均持久阻止继续旧上下文。

这些证据证明功能机制和版本边界，不证明真实业务问答正确率或实际 Token 节省比例。真实验收仍需要维护者提供代表性问题、已核验答案、适用条件、源码版本与负向样本，再离线比较命中覆盖、错误复用率、答案一致性、整体 P50/P95 与提供商实际用量。没有调用真实模型或编造这些指标。
